## 当前一句话状态

LADAR2 当前已经具备主链路闭环：LiDAR 通过 UART2 DMA 进入 MCU，MCU 结合编码器和电机速度估算每点时间/角度，再通过 CAN 双帧发给 Linux，上位机完成双帧重组、CSV 存储、CSV 回放和 XY 2D 点云显示。

项目现在的主要工作不是继续堆新功能，而是收口证据和文档：补 M3 恢复证据、统一 Linux 脚本入口命名、做 M5 长稳测试、再推进 M6/M7 的几何质量和展示材料。

## 当前最需要记住的设计约定

- 正式距离字段是 `distance_cm`，不是 `distance_mm`。
- MCU 时间是 `t_sample_us`，Linux 接收/重组时间是 `host_rx_time_us`，两者不能混用。
- `angle_tick` 是相对开机零位的单圈编码器计数，`angle_deg` 是由它派生出的角度。
- CAN 每个点发两帧：`0x123` 发距离/角度/质量，`0x124` 发时间/原始角度/状态。
- 当前异常帧策略是丢弃并计数：校验失败、低幅值、过近都不输出点。
- LiDAR parser 当前已具备显式状态机、checksum 失败滑动 1 字节重同步和内部诊断计数。
- 电机当前是单圈换向的双向闭环扫描，不是一直单方向旋转。
- Linux 侧已经具备实时接收和回放能力，文档入口已和当前 `can_recv4.py` 对齐。
