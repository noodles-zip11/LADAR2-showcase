## 2. 已经做成的主链路

当前项目已经不是“单点功能调通”状态，而是有一条完整主链：

```text
LiDAR UART
-> MCU DMA chunk
-> LiDAR 帧解析
-> 时间戳/角度配对
-> CAN 双帧发送
-> Linux 双帧重组
-> CSV 存储
-> CSV 回放
-> XY 2D 点云显示
```

已有证据集中在：

- `docs/spec_freeze/`
- `docs/m1/`
- `docs/m2/`
- `docs/m3/`
- `docs/m4/`

Notion 中 M2 的“输出角度同步误差预算”仍是未勾选。

但仓库里已经有：

更准确的说法是：

- 非机械项误差预算已完成。
- 机械误差实测值仍待补。
- 建议把 Notion 的 M2 状态改成“误差预算已完成，机械实测待补”，否则后续复盘容易误判。

### 3.2 M3 Notion 勾选偏乐观

Notion 中 M3 任务列表多项已勾选，但同一页 callout 又写了 M3 仍需补：

- 丢帧重组规则验证
- `DiagLogTask` 错误计数

- 双节点联调闭环证据

仓库 `docs/m3/README.md` 的判断更细：

- MCU 统计埋点已经落地
- LiDAR parser 已完成内部拆分、滑动重同步和显式 `LunaParseState` 状态机收口
- `DiagLogTask` 已有正常/故障样例
- Linux 最小重组闭环已完成
- 仍缺 `Bus-Off -> recovery` 板级实测证据
- 协议正文还需要补 Linux 双帧超时、覆盖、`seq` 回绕规则

所以 M3 现在应按“实现基本完成，证据和协议收口待补”处理。

### 3.3 M4 脚本入口不一致

`docs/m4/README.md` 里写的入口是 `can_recv4.py`。

当前仓库根目录实际看到的是：

- `can_recv4.py`

这说明 M4 文档和实际脚本命名已经漂移。建议下一步先统一：

- 要么把文档改成 `can_recv4.py`
