# 电机控制逻辑

更新时间：2026-04-20

本文只讲电机和角度同步相关逻辑。它对应 Notion 里的 M2，也对应仓库里的 `docs/m2/`。

## 1. 电机硬件抽象

电机驱动由两个方向 GPIO 和一个 PWM 输出组成：

| 信号 | 代码位置 | 作用 |
| --- | --- | --- |
| PC0 | `AIN1_SET` / `AIN1_RESET` | 电机方向 A |
| PC1 | `AIN2_SET` / `AIN2_RESET` | 电机方向 B |
| TIM1 CH1 / PE9 | `__HAL_TIM_SET_COMPARE(&htim1, TIM_CHANNEL_1, value)` | PWM 占空比 |
| TIM2 / PA0 PA1 | 编码器模式 | 电机转轴角度/速度反馈 |

TIM1 的 `Period = 999`，所以当前 PWM 命令范围是 `0..999`。

## 2. `Motor_Set()` 的含义

`Motor_Set(int speed)` 用 `speed` 的符号决定方向，用绝对值决定 PWM：

- `speed > 0`：PC0 set，PC1 reset
- `speed < 0`：PC1 set，PC0 reset
- `speed >= 0`：CCR 写 `speed`
- `speed < 0`：CCR 写 `-speed`
- 大小限幅到 `999`

注意：`speed == 0` 时只会把 PWM compare 写 0，不会额外改方向 GPIO。这个行为当前没有问题，因为零速时 PWM 为 0，但如果后续要做刹车/滑行语义，需要单独定义。

## 3. 编码器和角度参数

当前项目参数在 `Core/Inc/main.h`：

```text
ENC_PPR = 7
GEAR_RATIO = 210
四倍频
counts_per_rev = 7 * 210 * 4 = 5880 count/rev
```

这意味着：

```text
angle_per_count = 360 / 5880 = 0.061224 deg
```

`Get_Realtime_Motor_Angle()` 是一个简单的原始角度读取函数：

```text
raw_count = TIM2 counter
current_count = raw_count % counts_per_rev
angle = current_count / counts_per_rev * 360
```

但当前主链路的正式点角度不靠这个函数直接生成，而是在 `luna_input()` 里基于连续 32 位编码器计数和开机零位计算。

## 4. 电机控制任务总体目标

`MotorCtrlTask1` 当前不是单方向恒速，而是“单圈换向的双向闭环扫描”：

1. 正向扫约 1 圈。
2. 到达 1 圈累计计数后，目标速度置 0。
3. 等实际速度降到接近 0。
4. 翻转方向。
5. 按 1200 ms 斜坡恢复到反向目标速度。
6. 反向扫约 1 圈后重复。

这套设计和 LiDAR 点云角度语义的关系是：输出真实物理角度，不人为把反向扫描重排成单调锯齿角。

## 5. 控制参数

`MotorCtrlTask1` 当前关键参数：

| 参数 | 当前值 | 含义 |
| --- | --- | --- |
| `control_period_ms` | `50 ms` | 速度计算和控制周期 |
| `counts_per_rev` | `5880` | 一圈编码器计数 |
| `reverse_interval_counts` | `1 * counts_per_rev` | 每转 1 圈触发换向 |
| `target_speed_abs_rps` | `0.15 rps` | 目标转速幅值 |
| `reverse_resume_speed_rps` | `0.015 rps` | 判定可以换向的低速阈值 |
| `reverse_ramp_ms` | `1200 ms` | 换向后速度斜坡时间 |
| `startup_pwm` | `220` | 斜坡起点基准 PWM |
| `base_pwm` | `430` | 稳态基准 PWM |

## 6. 测速逻辑

每 50 ms：

```text
delta_count = current_encoder_count - last_encoder_count
rev = delta_count / counts_per_rev
m1_speed = rev / dt_s
```

`delta_count` 用 `int16_t` 承接，所以能处理 TIM2 16 位计数器小范围回绕。

`g_speed_valid` 不是一开始就有效。代码要求看到至少 2 次非零速度更新后才置位，这样可以避免刚启动时速度估计还没稳定就被 LiDAR 角度回推使用。

另外代码里有一个方向约定：

```c
float m1_speed_ctrl = -m1_speed;
```

也就是说，闭环控制使用的速度符号和原始编码器测速符号相反。这通常是在硬件接线、编码器方向或电机方向定义之间做符号补偿。

## 7. PID 逻辑

PID 参数在 `PID_init()`：

| 参数 | 当前值 |
| --- | --- |
| `kp` | `180` |
| `ki` | `210` |
| `kd` | `0` |
| `max_output` | `400` |
| `max_iout` | `500` |
| `d_filter_alpha` | `0.2` |

`PID_realize()` 做了这些事：

1. `err = target_val - actual_val`
2. 积分候选：`err_sum + err * dt`
3. 积分限幅：`±max_iout`
4. D 项按误差变化率计算并低通，但当前 `kd = 0`，所以实际不参与输出
5. 输出：`kp * err + ki * i_candidate + kd * d_out`
6. 总输出限幅：`±max_output`
7. 抗积分饱和：输出已经打满且误差还在同方向推时，不更新积分

PID 输出 `trim` 不是最终 PWM，而是叠加在方向基准 PWM 上：

```text
pwm_cmd = scan_dir * commanded_base_pwm + trim
```

## 8. 换向状态机

当前换向逻辑可以理解为两个状态：

### 正常运行

- `reverse_pending == 0`
- 根据 `run_elapsed_ms` 计算斜坡比例 `target_scale`
- 目标速度是 `scan_dir * 0.15 * target_scale`
- 累加本段位移 `segment_travel_count += abs(delta_count)`
- 如果累计达到 1 圈，则：
  - `reverse_pending = 1`
  - 目标速度置 0
  - `PID_Reset()`

### 等待换向

- `reverse_pending != 0`
- PWM 命令固定为 0
- 观察 `abs(actual_speed)`
- 当 `abs(actual_speed) <= 0.015 rps`：
  - `scan_dir = -scan_dir`
  - 清零本段计数
  - `reverse_pending = 0`
  - 记录新的 `dir_resume_ms`
  - `PID_Reset()`
  - 目标速度从 0 开始斜坡恢复

这个策略的好处是没有直接反打，换向过程更可控。

## 9. 电机和 LiDAR 同步的关系

电机任务维护全局 `m1_speed` 和 `g_speed_valid`，解析任务调用 `luna_input(..., m1_speed)`。

`luna_input()` 用 `m1_speed` 把 chunk 到达时刻的编码器位置回推到每个 LiDAR 帧的估计采样时刻。也就是说：

- 电机速度越稳定，角度回推误差越小。
- 换向阶段速度接近 0 时，回推量自然变小。
- 如果 `g_speed_valid == 0`，解析侧走退化路径，角度只用 chunk 级编码器位置。

所以 M2 的稳速验证不是孤立的电机任务，它直接影响点云几何质量。

## 10. 已有验证结论

根据 `docs/m2/01_稳速验证.md`：

- 当前已完成“双向闭环稳速 + 周期换向”。
- 目标速度在 `+150 mrps` 和 `-150 mrps` 之间周期切换。
- 换向时先降到 0 附近，再斜坡恢复反向目标。

稳态统计：

| 方向 | 实际速度均值 | 最大绝对误差 | 标准差 |
| --- | --- | --- | --- |
| 负向 | `-150.16 mrps` | `13 mrps` | `5.57 mrps` |
| 正向 | `150.77 mrps` | `17 mrps` | `6.83 mrps` |

根据 `docs/m2/03_角度同步误差预算.md`：

- 编码器分辨率误差：`±0.0306°`
- 配对时刻误差：`±0.0211°`
- 转速波动误差：`±0.0322°`
- 非机械项 RSS 合成：约 `±0.0492°`
- 非机械项线性保守上界：约 `±0.0840°`
- 机械误差仍待实测

## 11. 当前后续优化点

- 补机械误差实测：固定目标、多圈重复采样，回填 M2 误差预算。
- 观察正向接近换向前的速度下探，必要时调 `base_pwm`、PID 参数或换向阈值。
- 如果后续点云出现方向相关畸变，优先核查 `m1_speed_ctrl = -m1_speed` 这个符号约定是否和 LiDAR 回推的 `m1_speed` 符号完全一致。
- 如果要做刹车/滑行控制，需要明确 `Motor_Set(0)` 的 GPIO 语义。
