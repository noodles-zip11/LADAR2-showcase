# M2 距离-角度配对策略

## 1. 目标

在当前“单圈换向”的双向扫描模式下，将 LiDAR 距离帧与电机角度进行稳定、可解释、可回放的配对，输出每个点对应的：

- `t_sample_us`
- `angle_tick`
- `angle_deg`
- `distance_cm`

本页只说明当前正式配对策略，不展开误差预算。

## 2. 当前扫描运动策略

当前电机并非持续单方向转动，而是：

- 每累计转过 `1 rev`
- 先减速到 0
- 等速度低于阈值后翻转方向
- 再以斜坡恢复到反向目标速度

因此，当前配对策略必须满足两个要求：

1. 能在正向与反向都成立
2. 在换向经过零速附近时，仍保持时间和角度语义一致

## 3. 输入信息

当前配对链路依赖以下输入：

- LiDAR UART 原始 9 字节帧
- UART DMA + IDLE chunk 到达时刻 `luna_chunk_rx_time_us`
- chunk 到达瞬间的编码器快照 `luna_rx_encoder_count32`
- 当前测速结果 `motor_speed_rps`

相关常量：

- 单帧长度：`LUNA_FRAME_LEN = 9`
- 串口单字节时间：`UART_CHAR_US = 87`
- IDLE 保护时间：`UART_IDLE_GUARD_US = 87`
- 编码器每圈总计数：`ENC_PPR * GEAR_RATIO * 4 = 5880`
当前实现补充：

- 上述 TF-Luna 协议常量当前集中在 `Core/Inc/luna_protocol.h`
- `luna_input()` 当前通过显式 `LunaParseState` 状态机组织解析路径，只在通过帧头、checksum 和质量过滤后才进入时间/角度估算
- checksum 失败时当前 parser 滑动 1 字节继续重同步；该行为只影响解析恢复，不改变成功点的配对公式
- 非帧头、重同步和成功入队分别由 `luna_header_skip_cnt`、`luna_resync_cnt`、`luna_frame_ok_cnt` 进行内部计数

## 4. 总体思路

当前方案不是“按圈均分角度”，而是：

1. 在 chunk 到达时抓时间戳和编码器快照
2. 在 chunk 内定位每个 9 字节 LiDAR 帧
3. 对每个帧回推 `t_sample_us`
4. 用当前速度把 chunk 时刻的编码器位置回推到该帧采样时刻
5. 再把连续编码器计数折叠成单圈角度

这套流程在正向和反向共用一套公式，方向信息自然体现在速度符号和连续编码器计数方向上。

## 5. 正式策略

### 5.1 Chunk 级快照

在 `HAL_UARTEx_RxEventCallback` 中，`USART2` 收到 DMA + IDLE 事件后，立即记录：

- `chunk_time_us = micros_now()`
- `enc16 = TIM2 当前编码器计数`
- `enc32 = encoder_take_snapshot32(enc16)`

并写入 `LidarChunk`：

- `luna_chunk_rx_time_us`
- `luna_rx_encoder_tick16`
- `luna_rx_encoder_count32`

这一步为整个 chunk 建立时间与角度锚点。

### 5.2 帧级时间回推

在 `luna_input()` 中解析 chunk 内每个 9 字节帧。

对当前帧，先计算帧尾在 chunk 中的位置，再回推帧尾时间：

```text
frame_end_us =
    chunk_rx_time_us
    - UART_IDLE_GUARD_US
    - bytes_after * UART_CHAR_US
```

然后以帧中心时刻作为该点采样时间：

```text
t_sample_us = frame_end_us - (LUNA_FRAME_LEN * UART_CHAR_US) / 2
```

### 5.3 帧级角度回推

若当前速度有效，即 `g_speed_valid != 0`，则按当前速度将编码器快照回推到 `t_sample_us`。

先将转速换算为“每微秒走过多少编码器计数”：

```text
ticks_per_us = motor_speed_rps * counts_per_rev / 1e6
```

再计算当前帧与 chunk 锚点之间的时间差：

```text
dt_us = chunk_rx_time_us - t_sample_us
```

据此回推编码器计数：

```text
backtrack_ticks = round(ticks_per_us * dt_us)
sample_count32 = chunk_encoder_count32 - backtrack_ticks
```

其中：

- 正向时，`motor_speed_rps` 为正
- 反向时，`motor_speed_rps` 为负

因此双向配对不需要额外分支，方向由速度符号自动体现。

### 5.4 零位与单圈角度

系统采用“开机零位”策略：

- 第一个成功输出点的 `sample_count32` 被锁定为 `g_zero_offset_count32`
- 后续角度全部相对这个零位计算

单圈角度计数计算为：

```text
angle_tick = fold_count32_to_rev(sample_count32 - g_zero_offset_count32, counts_per_rev)
```

再换算为：

```text
angle_deg = angle_tick / counts_per_rev * 360
```

说明：

- 当前输出的是物理单圈角度
- 即使扫描方向改变，角度语义仍然保持“相对开机零位的真实转轴角度”

### 5.5 换向阶段的语义

当前换向过程由 `MotorCtrlTask1` 控制：

- 到达单圈阈值后，目标速度先置 `0`
- 等待实际速度降到阈值以下
- 再翻转 `scan_dir`
- 重新按斜坡恢复到反向目标

对配对链路的影响是：

- 配对仍继续使用连续编码器计数
- 在接近零速时，`ticks_per_us` 也随之变小
- 因此回推量自然减小，不需要单独“镜像角度”

也就是说，当前系统输出的是**真实物理角度**，不是“人为重排后的锯齿角”。

### 5.6 退化路径

在以下情况下，不走完整回推路径：

- 当前速度无效
- 当前帧不满足正常回推条件

此时退化为：

- 时间仍按 chunk 锚点近似回推
- 角度直接使用 chunk 级编码器位置
- `status` 附带 `LIDAR_STATUS_ESTIMATED`

## 6. 为什么采用这套策略

### 6.1 不依赖整圈缓存

每个点到达后即可输出，不需要等整圈结束后再统一算角度。

### 6.2 正反向共用一套公式

方向差异直接由：

- 连续编码器计数方向
- 当前测速符号

共同体现，不需要为反向扫描另写一套配对逻辑。

### 6.3 与误差分析直接衔接

后续误差预算可以直接围绕以下项展开：

- 编码器分辨率
- 帧中心时刻近似误差
- 转速波动误差
- 机械误差

## 7. 输出语义

当前正式输出语义如下：

| 字段 | 含义 |
| --- | --- |
| `t_sample_us` | 基于 UART 帧中心时刻估计得到的单点采样时间 |
| `angle_tick` | 相对开机零位的单圈编码器计数 |
| `angle_deg` | `angle_tick` 换算得到的真实物理角度 |
| `distance_cm` | LiDAR 单点距离 |
| `status` | 点级估计/退化路径标记 |

## 8. 结论

当前工程的距离-角度配对策略已经固定为：

- 先在 chunk 级抓时间和编码器快照
- 再在帧级回推采样时刻
- 最后按当前速度和连续编码器计数回推物理角度

这套设计适用于当前“单圈换向”的双向扫描模式，并且保持了正向、反向、换向阶段的一致时间与角度语义。
