# M3 错误统计与恢复样例

## 1. 结论

当前已经归档 MCU 侧故障态与 ACK fault recovery `DiagLogTask` 样例，能够证明：

- `DiagLogTask` 的 M3 CSV 已在 MCU 侧实际输出
- CAN 发送失败计数会持续增长
- CAN 错误位图和错误中断计数会持续刷新
- 恢复后 `can_tx_ok_point_cnt` 重新增长，错误计数停止增长

本次故障注入方式没有触发 Bus-Off，因此没有证明：

- `HAL_CAN_ERROR_BOF` 出现
- `can_recovery_cnt` 在 Bus-Off 恢复后增加

此外，当前已经归档一段 MCU 正常态 `DiagLogTask` 样例，可作为正常链路对照。

因此，本页当前可以作为“正常态 + ACK 故障态 + ACK 恢复态样例页”。`Bus-Off -> recovery` 不作为 M3 当前收尾证据。

## 4. 样例解读

从这段故障态样例可以直接看到：

- `can_tx_ok_point_cnt` 固定在 `5576`
- `can_tx_fail_point_cnt` 持续增加
- `can_tx_fail_frame_cnt` 持续增加
- `can_error_irq_cnt` 持续增加
- `can_last_error_code` 持续保持为非零值 `0x00200063`
- `can_bus_off_cnt=0`
- `can_recovery_cnt=0`

这说明当前故障更像是“持续错误风暴”而不是“已进入并退出 Bus-Off”的闭环。

## 5. `can_last_error_code` 粗解

当前样例中的：

- `0x00200063`

至少包含以下错误位：

- `0x00000001`：`HAL_CAN_ERROR_EWG`
- `0x00000002`：`HAL_CAN_ERROR_EPV`
- `0x00000020`：`HAL_CAN_ERROR_ACK`
- `0x00000040`：`HAL_CAN_ERROR_BR`
- `0x00200000`：`HAL_CAN_ERROR_PARAM`

这说明当前链路中至少出现了：

- Error Warning
- Error Passive
- ACK 错误
- Bit Recessive 错误
- 参数错误位

当前样例中没有看到：

- `HAL_CAN_ERROR_BOF`

因此本样例不能用于证明 `Bus-Off -> recovery`。
