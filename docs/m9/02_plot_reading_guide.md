# M9 附录图读法指引

M9 当前不作为强证明项。读图目标不是证明规则已经有效，而是说明这版规则流程的边界：能跑、能输出候选点，但现有 M6 known_scenes 没有提供足够的异常证明价值。

## 1. 先看哪张图

优先看总览图：

```text
docs/m9/runs/rule_based_v1/known_scenes_contact_sheet.png
```

这张图只包含 M6 已知场景数据，适合先看全局分布。不要用未知 replay 图去讲墙面或箱体效果。

墙面有效区域要看裁剪图：

```text
docs/m9/runs/rule_based_v1/known_scenes_wall_roi_contact_sheet.png
```

墙面 ROI 沿用 M6 口径：`angle_deg >= 350` 或 `angle_deg <= 40`，且 `distance_cm = 35 -> 100`。

## 2. 图例怎么读

- 蓝点 `kept`：规则过滤后保留的点。
- 红点 `filtered`：规则判断为候选异常的点。
- 红点不是人工真值异常，只是规则候选异常。
- 没有红点不代表绝对无异常，只代表当前规则没有筛出候选异常。

## 4. 当前判断

这版 M9 不能强行讲成“有效提升了墙面/箱体图形质量”。

更准确的判断是：

- 箱体三组没有触发规则过滤，说明当前数据在规则定义下没有明显点级异常。
- 墙面三组的红点大多落在 M6 墙面 ROI 外，不能作为墙面有效区域异常证据。
- 墙面 ROI 内几乎没有红点，说明 M9 当前只是保守质量门，不是强效果过滤器。
- M9 的价值主要是保留规则流程骨架、输出格式和边界说明，为后续带真实异常/动态目标的数据做准备。
- 在当前封箱材料里，M9 应弱化为附录，不作为核心亮点。

## 5. 面试表达

可以这样说：

```text
M9 我只把它作为附录性质的离线规则流程。它不会训练模型，也不修改实时链路，只验证 CSV 数据能进入规则过滤、报告和对比图流程。当前数据没有证明它能有效改善墙面或箱体图形：箱体没有触发过滤，墙面有效 ROI 内也几乎没有过滤点，红点主要落在非目标区域。所以我不会把它作为核心成果，只把它保留为后续有真实异常样例和人工标签之后继续扩展的入口。
```

不要这样说：

```text
M9 已经能准确识别异常点。
M9 有 precision/recall。
M9 是 AI 模型。
未知 replay 里的 5 月 7 日数据是墙面或箱体。
M9 已经显著改善了 M6 墙面图形。
M9 是这个项目的核心创新点。
```

## 6. 下一步如果继续做

只有在新增带现场记录的数据后，才继续扩展：

1. 采集时记录场景：墙面、箱体、动态目标或异常制造方式。
2. 让 M8 生成数据集和标签。
3. 让 M9 重新跑规则过滤。
4. 人工看红点是否真是异常，再讨论误删和漏删。
