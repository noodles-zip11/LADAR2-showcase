# M0 规格冻结页

## 1. 目标

停止语义漂移，把当前真实实现写成正式设计结论，并明确哪些点已经冻结，哪些点属于后续验证边界。

## 2. 冻结范围

- MCU 点结构与内部调试字段
- CAN 报文定义
- Linux/CSV 字段
- 时间戳语义
- 单位与字段命名

## 3. 已冻结结论

### 3.1 单位与命名

- 主距离字段冻结为 `distance_cm`
- 不再将 `distance_mm` 作为正式字段
- 当前正式字段命名统一为：
  - `host_rx_time_us`
  - `t_sample_us`
  - `distance_cm`
  - `angle_tick`
  - `angle_deg`
  - `quality`
  - `status`

### 3.2 时间戳语义

- `t_sample_us`
  - 产生位置：MCU
  - 当前定义：按 UART 帧中心时间估计得到的每点时间戳
  - 用途：点序恢复、角度配对、点云几何
- `host_rx_time_us`
  - 产生位置：Linux
  - 当前定义：Linux 侧接收并完成该点重组时的本地时间
  - 用途：链路延迟、抖动、回放和日志对齐
- `luna_chunk_rx_time_us`
  - 产生位置：MCU
  - 当前定义：DMA + IDLE chunk 的接收锚点
  - 用途：内部估计与调试
  - 不作为正式点字段对外传输

### 3.3 零位与圈边界

- 零位方案已冻结为“开机零位”
- 当前系统无自动回零硬件，采用“第一个成功输出点”的 `sample_count32` 作为本次运行零位
- `angle_tick` 与 `angle_deg` 当前均相对 `g_zero_offset_count32` 计算
- 圈边界定义基于连续编码器计数
- 内部圈号定义为：
  - `rev_id = floor((sample_count32 - g_zero_offset_count32) / counts_per_rev)`
- 当 `rev_id` 变化时，视为跨过圈边界并进入新圈
- `rev_id` 当前仅作为 MCU 内部调试/统计语义，不进入正式点结构，不上 CAN，不进正式 CSV

### 3.4 当前实现快照

当前 `lidar_point_t` 的正式字段为：

```c
typedef struct {
    uint32_t t_sample_us;
    uint16_t angle_tick;
    float angle_deg;
    uint16_t distance_cm;
    uint8_t quality;
    uint8_t status;
    float tmp;
} lidar_point_t;
```

当前 `LidarChunk` 的内部调试字段为：

```c
typedef struct {
    uint8_t data[64];
    uint16_t count;
    uint8_t ready;
    uint32_t luna_chunk_rx_time_us;
    uint16_t luna_rx_encoder_tick16;
    int32_t luna_rx_encoder_count32;
} LidarChunk;
```

当前 CAN 报文为：

- `0x123`：`seq + distance_cm + angle_deg(float bits) + quality`
- `0x124`：`seq + t_sample_us + angle_tick + status`

### 3.4 异常帧处理策略

- `checksum` 校验失败帧：不输出点，并累加 `checksum_fail_cnt`；当前 parser 采用滑动 1 字节重同步策略，并累加 `luna_resync_cnt`
- `AMP_LOW` 帧：直接丢弃，不输出点，并累加 `amp_low_cnt`
- `TOO_NEAR` 帧：直接丢弃，不输出点，并累加 `too_near_cnt`
- `status` 字段仅随成功输出的点发送
- `LIDAR_STATUS_ESTIMATED` 用于标记已输出点的时间或角度采用估计值
- `uart_chunk_drop_cnt`、`parser_overflow_cnt`、`lidar_point_drop_cnt` 继续作为链路级计数器保留，不映射为单点状态
- 链路级丢点当前仅做计数，不做补点、不做重发、不做插值，系统继续运行
- `luna_header_skip_cnt`、`luna_resync_cnt`、`luna_frame_ok_cnt` 属于 MCU 内部解析诊断计数器，不进入正式点结构、不上 CAN
- `LunaParseState` 属于 MCU 内部 parser 实现细节，仅用于组织帧头搜索、帧校验、帧解码和点输出，不改变冻结协议语义

## 4. 当前冻结边界

- M6 前无协议语义待决策项
- M2 机械误差实测值转入 M6 几何质量与重复性测试
- M3 `Bus-Off -> recovery` 仍需补板级实测证据，但不改变已冻结协议语义

## 5. Linux 接收端重组规则

- Linux 接收端按 `seq` 重组 `0x123` 与 `0x124` 两类帧。
- `seq` 是 1 字节有效值，取值范围 `0..255`，发送端按 `uint8_t` 自然回绕；`255 -> 0` 是正常连续序列，不视为异常。
- 接收端为每个 `seq` 保留待配对的 A 帧与 B 帧。只有同一 `seq` 的 `0x123` 和 `0x124` 都到达后，才输出一个完整点。
- 双帧配对超时固定为 `50 ms`。超过 `50 ms` 仍未配齐的 pending 半帧直接淘汰，并计入 timeout/drop 统计。
- 同一 `seq` 下，如果新的 `0x123` 到达时旧 `0x123` 尚未完成配对，则新帧覆盖旧帧，并计入 `overwrite_a` 统计。
- 同一 `seq` 下，如果新的 `0x124` 到达时旧 `0x124` 尚未完成配对，则新帧覆盖旧帧，并计入 `overwrite_b` 统计。
- 接收端不补点、不重发、不插值；所有丢帧、超时和覆盖只进入统计摘要，主链路继续运行。

## 6. 冻结规则

- 单一语义只保留一个正式字段名
- MCU 时间与 Linux 时间分离命名
- 内部估计锚点字段不混入正式点字段
- 先冻结语义，再做后续接口或协议重构
